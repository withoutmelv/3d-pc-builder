# 3D 装机工作室

基于 React + Vite + JavaScript + Three.js + Fastify 的 Web 装机 MVP。
前端提供中文全屏 3D 装机工作台，后端采用 router → controller → service 分层，配合 Fastify hooks middleware、统一错误码和 SQLite 配置持久化。

## 运行

使用 Node.js 22.13+（内置 `node:sqlite`），推荐 Node.js 24 LTS。首次运行：

```bash
npm install
npm run dev
```

- Web：<http://127.0.0.1:5173>
- API：<http://127.0.0.1:3001/api/parts>
- 开发时 Vite 将 `/api` 代理到 Fastify。

生产模式本地验证：

```bash
npm run build
npm start
```

生产模式由 Fastify 同时提供前端与 API，入口为 <http://127.0.0.1:3001>，支持前端路由直接刷新。
请先停止占用 3001 端口的开发 API，或指定 `PORT=3002 npm start`。

```bash
npm test
npm run format:check
```

## 沉浸式装机视角

默认入口 `/workbench`；配件货架区域通过 `/builder` 打开。

工作台、托盘和零件表面不显示中英文标签，保留方向角标和内存缺口。工作台只保留主机部件、操作垫、零件托盘及装配工具，已移除台灯和显示器。不显示人物双手；拿起的物品跟随视角，场景中的轮廓显示实际落点。

点击 3D 场景后移动鼠标转动视线，用视野中心的简洁十字准星对准物品。顶部居中显示左键拿放与交互、长按拧螺丝、R 旋转、WASD 移动及 Esc 菜单提示。瞄准可交互目标时，目标高亮、准星轻微放大并变绿，顶部提示下方显示目标名称；底部、左右两角、菜单与操作通知继续收起。按 Esc 释放鼠标返回菜单，手中物品保持不变。浏览器允许时使用 Pointer Lock；不支持锁定的内置预览使用兼容鼠标模式，只能在窗口范围内转头，移出画布或退出操作后停止。鼠标灵敏度已降低，俯仰限制在向下约72°、向上约60°，避免视线过度翻转。完整体验建议在允许 Pointer Lock 的桌面浏览器打开本地地址。

| 操作            | 控制方式                                                          |
| --------------- | ----------------------------------------------------------------- |
| 拿起 / 放下     | 视野中心对准物品或落点，点击鼠标左键；按住不重复触发              |
| 扣具 / 工具     | 瞄准压盖、内存卡扣或螺丝刀，点击鼠标左键                          |
| 拧紧 / 松开螺丝 | 选择螺丝刀，瞄准固定点，按住鼠标左键约 0.7 秒；松开或移开视线取消 |
| 旋转物品        | `R` 转 90°，`Shift + R` 反向；按住不连转                          |
| 调整手持高度    | `Shift + 滚轮`，不会改变物品最终支撑面                            |
| 移动            | `WASD` / 方向键，`Shift` 加速                                     |
| 升降视角        | `Space` 升高、`C` 降低                                            |
| 返回菜单        | `Esc`，不放下也不归位手中物品                                     |
| 取消拿取        | 菜单内“放回原位”按钮                                              |

CPU、内存和 M.2 磁盘使用带角标、缺口的半透明落位预览；方向错误时保留当前朝向并显示橙色，对齐后变绿。安装包含约 0.32 秒的贴近与压入动画，系统减少动态效果偏好下直接落位。安装、扣具和螺丝完成时播放轻量本地合成音效，菜单顶部可静音；成功或受阻原因短暂显示在原有顶部提示区。音频不可用时不影响操作。

新工作台的 CPU 和两根内存默认相对主板旋转 180°，需要先对齐 CPU 角标或内存缺口再安装；方向错误时落点轮廓为橙色，顶部提示按 R 旋转。保存过的布局仍保留各自朝向。

主板、CPU、两根内存、侧板和机箱可放到桌面及工作台周围的空闲地面，位置和角度随进度保存。落点跟随视线；转头不会改变零件的摆放朝向。靠近对应安装口时，用轮廓显示落点并自动校正不超过45°的小偏差，90°或180°的错误朝向仍需手动旋转；旧存档的任意角度保持兼容。没有指定必须使用的停放区；仅阻止物品相互穿透、放进桌体、超出房间或不符合接口方向的安装。暂不模拟堆叠、自由落体与任意悬空停放。

“参考流程”只提供可收起的建议，不控制顺序。可先装空主板进机箱再安装 CPU/内存，也可从 B2 内存开始，在托盘或桌面上的主板装配。移动主板前需锁定或取下未固定的附属部件，移动机箱前需固定内部主板；盖住的侧板会阻挡内部操作。

两根内存都能安装到 A2 或 B2；物品编号不绑定插槽。打开对应卡扣后，可把未锁定的内存直接换到另一个已打开的空槽，或取下放回桌面。移动、安装与取出一根内存不会改变另一根的身份或松散摆放位置。

右下角“操作辅助”保留无指针锁定时的等效按钮，使用同样装配规则。拿着物品时先放下或归位再保存。当前采用鼠标控制的角色视角，不显示人物模型。当前包含主板、CPU、双内存与散热器装配，以及散热器风扇线的连接和拔除；M.2 磁盘支持插入、螺丝固定和拆卸；显卡支持 PCIe 卡扣、插入和挡板螺丝固定；电源支持独立入箱、四颗螺丝固定与拆卸。已支持主板 24Pin、CPU EPS 8Pin 和显卡 PCIe 8Pin 接线，模拟通电尚未实现。主板四个固定点与散热器两个固定点为交互演示。

## 工作台渲染性能

工作台按独立部件与可动扣具的边界合并同材质静态网格，保留几何细节与碰撞目标；只在镜头、物品、扣具或界面状态变化时重绘。阴影使用 1024 × 1024 贴图，仅在物品发生变化时更新。渲染倍率上限为 1.25，缓冲区不超过约 150 万像素，避免 Windows 显示缩放和高分辨率屏幕放大 GPU 负担。

模型结构检查：`node scripts/workbench-model-stats.js`。加入双风扇散热器、硅脂管、M.2 插槽、PCIe 卡扣及电源位固定螺丝后，模型统计合计 140 个网格、12,178 个三角面（含 16 颗螺丝），无文字贴图；此前批处理优化将网格从 564 个降至 113 个。`npm test` 包含尺寸、细节、扣具独立运动和工具材质隔离验证。

2026-09-10 本机内置 Chromium 对比（macOS、1280 × 720 CSS、设备倍率 2、默认视角）：主画面每帧绘制提交 584 → 116，渲染缓冲区 2240 × 1260 → 1600 × 900。各采集三组 120 帧，循环 CPU 耗时中位数约 2.4 → 1.0 ms；测量时强制连续渲染以比较相同场景，临时采样代码已删除。两版都受本机 120 Hz 刷新率限制，因此这些数据只证明本机渲染开销降低，不代表 Windows 集成显卡实测帧率；目标电脑需要刷新页面后复测转头与移动。

## 散热器装配

散热器位于操作垫后方，硅脂管位于螺丝刀后方；二者均无表面文字。硅脂管和螺丝刀可通过准星左键拿取/归位，或从菜单切换。推荐先锁定 CPU，用硅脂管对准 CPU 左键涂硅脂，切换回手后拿起散热器，按 R 对齐并放入。切换螺丝刀，对准左右固定点分别按住左键约 0.7 秒，再切换回手，点击主板风扇接口接线。短按或移开准星会取消固定。辅助面板提供同规则按钮。

可先在托盘上的主板安装散热器，再移动完整组件；也可先入箱再装。未固定散热器会阻止移动主板。拆卸需先拔风扇线、松开两颗螺丝，再拿走散热器；放下取出的散热器后硅脂状态清空，装回需重新涂。侧板关闭时不能操作内部，散热器遮挡 CPU 压盖时不能打开压盖。风扇线采用点击接口连接的简化交互。

散热器进度保存在可选的 `assembly.cooling` 中：`{placed, paste, screws:[boolean,boolean], fanConnected}`，松散位置保存在 `layout.cooler`。旧存档缺省为未安装，原有位置保留；新增散热器的默认位置被占用时会放到周围空闲地面。新保存的套件包含散热器，旧四配件存档仍可读取与编辑。

## 当前边界

所有商品名称、参数和价格均为演示数据，不是真实商品目录或报价。基础几何体用于体验和流程验证，不提供完整装配保证。暂未检查电源功率与接口、散热扣具、BIOS、内存净空。

未提供登录或用户隔离。默认仅监听 `127.0.0.1`；本版本用于本地单用户工作空间。

没有实时比价、FPS 预测、完整物理模拟、自由布线、水冷管路和精确碰撞检测。工作台按桌面/地面支撑面检测旋转占用并辅助安装口对齐，不模拟物品自由落体或堆叠。导出的 PNG 是包含展台背景的 3D 模型视图，不包含页面面板。

## API

成功响应：`{ "code": "OK", "message": "成功", "data": ... }`。
失败响应：`{ "code": "VALIDATION_ERROR", "message": "请求参数不合法", "data": null }`。

| 方法   | 路径                               | 作用                     |
| ------ | ---------------------------------- | ------------------------ |
| GET    | `/api/parts?category=gpu&q=TRIPLE` | 搜索配件                 |
| GET    | `/api/parts/:id`                   | 配件详情                 |
| POST   | `/api/builds/check`                | 计算参考总价与基础兼容性 |
| GET    | `/api/builds`                      | 配置列表                 |
| POST   | `/api/builds`                      | 创建配置                 |
| GET    | `/api/builds/:id`                  | 读取配置                 |
| PUT    | `/api/builds/:id`                  | 更新配置                 |
| DELETE | `/api/builds/:id`                  | 删除配置                 |

检查请求体：`{ "selection": { "case": "case-air", "gpu": "gpu-dual" } }`。
保存请求体在此基础上增加 `name` 字符串；普通配置和新房间的 `selection` 均可为空。手动装配记录另传 `assembly` 对象，保存实际选择的型号。旧演示套件 `KIT_SELECTION` 的存档继续兼容。新房间可逐件选配，已取出的配件需先拆下并放回推车再通过货架更换型号。

`assembly` 保存主板位置、CPU/两根内存的放置与锁定状态、压盖和卡扣、侧板及四个固定点，以及可选的 `layout` 桌面布局。`layout` 含 board/cpu/memory0/memory1/panel/case，各项为 `{x,z,rotation,y?}`（毫米、角度）；可选 `y` 表示支撑面，`0` 为桌面、`-462` 为地面。省略 `y` 的旧位置仍按桌面解析，无 `layout` 的旧进度使用默认布局并可继续编辑。旧记录为 `null`。更新省略该字段会保留原进度；清除需显式传 `assembly: null`。拿取中的鼠标位置属于临时交互，必须放下或放回后才能保存。

内存状态中的 `memory[0/1]` 和 `layout.memory0/memory1` 始终对应两件物品，`memoryOpen[0/1]` 对应 A2/B2 插槽的卡扣。可选字段 `memorySlots` 按物品记录槽位：`[1,0]` 表示第一根位于 B2、第二根位于 A2；未安装项为 `null`，新进度为 `[null,null]`。一个槽位最多容纳一根内存。旧 version 1 进度缺少该字段时，已安装物品按同编号槽位恢复；下一次编辑会补齐映射，不交换布局中的物品身份。共享状态动作 `memory-place` 使用 `{index: 目标槽位, partIndex: 物品编号}`；省略 `partIndex` 保留旧版同编号行为。`memory-open` / `memory-lock` 的 `index` 是槽位，`memory-remove` 的 `index` 是物品编号。

`selection` 只接受 case、motherboard、cpu、cooler、memory、gpu、storage、psu，对应值为配件 ID。后端校验 ID 和类别，并根据目录计算总价。

| 错误码           | HTTP |
| ---------------- | ---- |
| VALIDATION_ERROR | 400  |
| PART_NOT_FOUND   | 404  |
| BUILD_NOT_FOUND  | 404  |
| ROUTE_NOT_FOUND  | 404  |
| INTERNAL_ERROR   | 500  |

配件冲突作为成功检查结果返回，检查状态为 pass、conflict 或 unchecked；允许保存有冲突或未完成的草稿。

## 后续模型替换

当前 `modelKey` 指向 `web/src/three/models/index.js` 中的模型生成分支。安装位置独立存放于 `placement.js`。坐标统一为毫米：X 指向机箱正面、Y 向上、Z 指向玻璃侧。

后续接入某个 GLB 时，在模型工厂增加该资源的加载方式，统一到现有毫米尺寸和局部原点，保留 category 与 partId 对应关系。模型资源加载及取消、失败回退需要在该阶段实现；本版没有假装已经实现 GLB 加载。

主板 dimensions 为 [高度, 宽度, 厚度]，机箱为 [宽度, 高度, 深度]；其他类别的解释见各生成分支。替换模型时应按类别核对轴向，不能直接将任意 GLB 原始坐标套用。

## 配件货架区域

`/builder` 按 CPU、主板、内存、磁盘、散热器、显卡、电源、机箱分为八个 3D 货架。可点选模型或型号标签查看详情，也可进入鼠标视角通过 WASD 浏览。分类按钮平滑切换到对应货架，浅绿色货架边标记已选型号。

货架、推车和工作台现在共用一个 3D 场景。`/builder` 从货架视角进入，`/workbench` 从工作台视角进入；区域按钮只移动镜头，不跳页或重新创建场景。也可以使用 WASD 自行走动。每类选择一个型号，内存为双条套装；支持替换、移除、补齐推荐配件、清单和总价。

新房间的工作台和推车初始为空。配件选中后出现在侧面的推车上，用户使用左键逐件拿到工作台，拿走后推车不自动补货。更换型号前需拆下并放回推车。选件不强制一次选齐八类，不兼容的松散配件可以保留，实际安装时检查 CPU 插槽、内存代际和机箱尺寸。通过“保存进度”记录当前选件与分布，未保存前离开仍有提醒。

新存档使用可选的 `assembly.room: true`，其 `layout` 仅包含已经选择的零件。推车支撑高度为 `y: -80`，范围由 `shared/workbench-layout.js` 的 `CART` 定义；桌面与地面仍分别为 `0` 和 `-462`。推车目前为固定停靠位置，不模拟推行。旧存档保留原有配件位置，不自动搬到推车；已有选配清单首次进入房间时会把配件放入推车。

工作台保存实际型号 ID；磁盘、显卡、电源使用可选的 `layout.storage/gpu/psu` 记录位置，支持自由拿放、碰撞检查和存档恢复。旧存档不会添加这些配件。几何模型是统一安装尺寸的简化占位模型，尚不代表每个商品的精确外观和尺寸；已支持三组供电线的简化接线。M.2 安装会校验主板支持的存储接口，显卡装入机箱时会校验长度上限，电源安装会校验 ATX 规格和长度上限；电源功率、BIOS 等仍未校验。

验证：`server/test/shared-room.test.js` 覆盖部分选件、推车拿放、换件限制、安装匹配及同一房间的存档往返；旧选配存档测试继续保留。静态货架及推车合并为 86 个网格（包含独立的选中标记），`server/test/room-fixtures.test.js` 检查几何体和绘制预算。

## M.2 磁盘装配

从推车拿起磁盘，对准主板下半部的 M.2 插槽，按 R 对齐接口缺口后左键插入。磁盘先略微翘起；拿起螺丝刀，对准末端固定点按住左键，磁盘逐渐压平并固定。拆卸时先松开该螺丝，再用手拿走。可在推车、工作台或打开侧板的机箱内操作，不要求先安装 CPU 或内存。磁盘未固定时不能移动主板或整机；固定后随主板移动。

装配状态可选字段 `storage` 为 `tray`（未安装）、`seated`（已插入待固定）、`locked`（已固定）；旧存档缺省为 `tray`。`server/test/storage.test.js` 覆盖自由顺序、移动限制、拆卸、接口匹配、旧状态兼容及 API 存档往返。

## 显卡机械装配

打开主板 PCIe 插槽末端的卡扣，拿起显卡，按 R 对齐金手指方向，准星对准插槽后左键插入，卡扣自动锁定。显卡可先在推车或工作台上的主板安装，随后连同主板入箱；主板固定后，用螺丝刀对准显卡挡板固定点，长按左键固定。拆卸时先松开挡板螺丝，再打开 PCIe 卡扣并拿走显卡。卡扣未锁定时不能搬动主板；挡板螺丝未松开时不能从机箱取出主板。侧板关闭时不能操作内部。

当前用一颗挡板螺丝演示固定，显卡支持一组 PCIe 8Pin 供电线连接。显卡模型增加金手指缺口、挡板和接口，安装时立于主板上；型号长度通过目录校验，几何体仍采用统一安装尺寸。存档可选字段 `graphics` 包含 `placed`、`latchOpen`、`screwed`，旧存档缺省均为 `false`。`server/test/graphics.test.js` 验证自由装配顺序、卡扣及挡板限制、长度匹配和 API 存档往返。

## 电源机械装配

打开侧板后，将电源接口朝向机箱后部，按 R 对齐并左键放入独立电源位。电源可先于主板安装，也可在主板、显卡装好后安装。用螺丝刀对准后部四颗螺丝长按固定；未全部固定时不能搬动机箱。拆卸需松开全部螺丝并打开侧板。后部螺丝在侧板关闭时仍可操作。固定后的电源随机箱移动。

机箱主板安装原点调整至 `[-18,43,-70]`，同步移动支柱，为电源留出独立空间；机箱外形尺寸和房间摆放位置不变。电源采用统一占位尺寸，目录中的规格和长度在安装时校验，供电线已支持连接，供电能力和开机检查留待下一阶段。存档可选字段 `power` 包含 `placed` 和四项布尔数组 `screws`；旧存档默认未安装、未固定。`server/test/power.test.js` 覆盖独立安装顺序、固定与搬动限制、拆卸、兼容性、API 存档以及电源位与主板的空间和后部开口。

## 供电接线

主板和电源装入机箱后，可从电源旁左键拿起三种线头：主板 24Pin、CPU EPS 8Pin、显卡 PCIe 8Pin。对准对应接口左键连接；正确接口显示绿色，类型不匹配显示橙色并拒绝连接。再次对准已连接接口左键拔除，线头回到电源旁。拿着线头时左键空白位置可放回，Esc 打开菜单仍保留当前线头。操作辅助提供同规则按钮。三组接线顺序自由，CPU 供电插在主板上，不要求先装 CPU；显卡供电则要求显卡已经安装。

拆主板或电源前需拔下三组供电线，拆显卡只需先拔下显卡供电线；机械螺丝与扣具规则继续生效。机箱整体移动时线缆一起移动，关闭侧板后隐藏内部接线。连线采用固定路径，尚不支持手动理线、线长限制、多显卡供电口或 12V-2x6 等接口。此阶段不进行真实供电能力判断，不模拟通电。

存档可选字段 `wiring` 记录 `board/cpu/gpu` 三个布尔值，旧存档默认为未连接；手中选中的线头属于临时交互状态，接好或放回后才能保存。`shared/power-wiring.js` 定义线缆类型，`server/test/wiring.test.js` 覆盖接线顺序、错误插头、拆卸限制、存档往返和模型随动。供电模块增加 15 个动态网格，线缆端点未变化时复用几何体；该模块不计入模型工厂统计脚本。

## 简洁工作台界面

工作台已移除四角入口及对应界面：标题与名称编辑、配置列表入口、保存按钮、静音切换、区域快捷跳转、参考流程、操作辅助，以及悬浮工具栏和重置对话框。点击场景进入鼠标操作，Esc 释放鼠标；顶部操作提示和准星保留。工具、零件、扣具及供电线通过场景内左键交互。货架选件仍可通过点击货架模型进入。后端存档接口和已有存档读取保留，当前工作台没有保存入口，也不自动保存；前文涉及这些已移除按钮的流程为历史说明。
