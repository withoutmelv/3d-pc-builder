## 首要约束：自由操作

教程提供推荐顺序，不能转化为全局步骤锁。审核每一条限制时，先判断它对应的是哪一种情况：

- **机械限制**：零件占用同一位置、缺口不匹配、卡扣或螺丝仍扣住、目标被外壳遮挡。需要限制，但应说明具体冲突位置。
- **安装质量问题**：漏涂硅脂、忘撕膜、漏接线、风向不佳。允许用户操作，记录实际状态，通过轻量提示和后续验机反馈发现，不替用户自动纠正。
- **教学建议**：先装哪一个部件、先拧哪一侧、推荐哪个插槽。只提示，不阻断。
- **当前模拟能力限制**：不能模拟散落零件、线缆长度或真实碰撞时，应明确为简化，不能包装成装机必然规则。

型号插槽不匹配属于机械限制；供电不足、风扇测速缺失等运行问题不能一概当成“无法装上”。自由操作也不等于让不匹配的插头穿过实体接口。

## 优先修正项与代码证据

### 1. 风扇默认出风方向反了

教程 23:22–23:28、23:49–23:54：该示例从内存侧吸入，向 I/O 面板侧排出。对应[23:27 画面](audit-frames/fan-23-27.jpg)及转写。

代码 `web/src/three/workbench-models.js`：主板内存位置 x=60/87，I/O 区域 x=-102；`createCoolerFan()` 的电机支架在风扇局部 z=+7，风扇绕 Y 转 +π/2，故出风侧指向主板 +X，即内存侧。`web/src/three/workbench.js` 将两只风扇按相同零旋转挂在塔体上，没有把方向转回。

本轮用 Three.js 向量变换复核，局部 +Z 经该旋转变为 +X。该结论来自结构标记与坐标，不是运行中的流体模拟。

修正目标：默认/建议方向与画面一致；把风扇正反方向与钢丝扣是否能扣上分开。若同一安装位允许正反装，应保留玩家选择并给出气流后果，不应只允许系统认定的正确风向。左右互换需要结合实际扣具适配，不依赖物品编号直接拒绝。

### 2. 没涂硅脂被当作无法安装

`shared/assembly.js` 的 `cooler-place` 与 `validateAssembly` 都要求 `cooling.paste` 为真。现有 `server/test/cooling.test.js` 也断言不涂就拒绝，说明这不是偶发错误，而是旧规则本身不合适。

目标：允许漏涂落位，保留漏涂状态并提示；未来验机时反馈散热问题。底膜已有“允许安装但提示”的路径，可以保持一致。不能只删除动作拦截而遗漏状态校验、存档恢复和测试。

另外，`socket-lever-open` / `socket-open` 会直接把 `cooling.paste` 清成 false。释放扣具不是清洁动作，应避免凭空清除；如何表达拆装后的硅脂需在 CPU 表面状态中处理。

### 3. 接线受到没有实体依据的顺序锁

- `shared/assembly.js` 的 `fan-connect` 要求两个风扇均 locked，且塔体两颗螺丝拧紧；`validateAssembly` 也有固定依赖。前端 `fan-header` 仅在塔体落位后可点。
- `cable-connect` 要求 `power.placed && board === 'case'`，`Workshop.jsx` 拿线时还要求电源先入箱；线缆模型依附机箱，尚无桌面线长表达。
- 当前单个 `fanConnected` 使一根线连接后，另一只尚未接线的风扇也无法自由拿起。

目标：根据真实两端连接和长度约束操作，而不是根据章节顺序。桌面接线需同时调整线缆呈现，不能只去掉后端判断。教程没有要求用户先进行桌面接线；这是用户自由原则所需的产品行为，不伪称视频规定。

### 4. 拆卸和固定存在不必要的“一定先完成”

`workbench.js` 的散热螺丝目标根据 `cooling.screws[i]` 选择拧紧/旋出；深度 1/3、2/3 时仍是 false，页面只能继续拧紧，无法直接反向。底层 `cooler-unscrew` 其实支持部分深度归零。应补足中途撤回，左键仍是主要交互，不恢复四角按钮。

`gpu-screw` 要求主板四颗螺丝全部拧紧。建议改为安装孔对齐、挡板可接触等条件，未固定完整仅提示。

搬动带松散部件的整个主板目前被禁止，防止模型把未固定件当成已经黏住。它是未实现散落物理时的简化；与“单独拿起这块松动部件”必须区分。后续可改为只带走已固定件，其余留在支撑面，不能简单删除限制后让零件悬空跟随。

### 5. 型号尺寸与实体遮挡尚未统一

`shared/room.js` 在主板入箱时就检查散热器限高，即使侧板未关闭也会拒绝。应区分塔体是否碰到实体框架与侧板能否合上：只有实际相撞的位置限制安装，超出侧板平面则在合盖时限制。

目前主板、塔体仍使用通用几何；目录中的尺寸与安装模型并非全部一一对应。因此内存避让、散热塔挡住 M.2 等细节不能声称已真实模拟。应先使演示型号的几何与孔位一致，再按实体遮挡决定限制，不能硬编码成“先装内存再装散热”。

## 可以保留的简化

- 单击代表双手均匀按压内存，仍区分 seated 和 locked。
- 螺丝分三段表达进度，不模拟实际扭矩；交替拧紧只作建议。
- 钢丝扣用折弯圆线近似；一次点击同时操作一只风扇的两根扣具。
- 垫柱和对应支架作为一个拿放单元；背板暂不独立掉落。
- 当前目录为演示型号，先保证其内部一致，不为了覆盖教程全部型号扩大本轮范围。

## 后续修正：显卡固定顺序与侧板限高

- 主板和显卡已在机箱内落位、PCIe 卡扣闭合后，允许先固定显卡挡板，不再要求主板四颗螺丝全部拧紧。页面提醒尚有主板螺丝未固定；显卡挡板固定期间仍不能直接取出主板，关闭侧板仍会阻挡内部操作。
- 散热器限高改为合盖条件。允许先装主板再装高塔，也允许桌面预装后整体入箱；落位时提示具体高度与机箱限高，合盖时拒绝并说明可以敞盖或更换散热器。
- 此项仍以演示型号的规格值校验侧板净空，没有新增精确几何碰撞检测，也未重建不同高度的散热器模型。机箱实体框架、内存避让等碰撞仍是后续核对范围，不能将本轮称为完整物理模拟。
- 不改变 CPU 插槽、内存代际、显卡限长、未涂硅脂禁止安装、螺丝/扣具固定和拆卸约束。

## 后续修正：扣具操作不再清除硅脂

- AM5 独立压杆和旧联动扣具动作均不再清除硅脂。重新合盖锁杆后保留已涂状态，但未锁定 CPU 仍不能安装散热器。
- CPU 取出、摆放、重新放入时硅脂仍属于同一颗 CPU；硅脂网格改为 CPU 的子对象，随 CPU 一同移动，不再留在主板插槽上。
- 更换或移除 CPU 选配时清除旧 CPU 的硅脂状态，并且不修改操作前的状态对象。没有 CPU 的房间状态不能带有硅脂。
- 保留涂硅脂动作需要已锁定 CPU、未涂硅脂不能安装散热器，以及拆下散热器后要求重新涂硅脂的现有规则。本轮没有新增清洁工具和硅脂残留/污染模拟。

验证：118 项测试通过，构建和格式检查通过。新增覆盖两套扣具动作、解锁仍阻止装散热器、原 CPU 取出再放入、更换 CPU 清除且不污染旧状态，以及解锁/开盖/取出时的 API 保存恢复。硅脂随模型移动的完整浏览器拿放流程尚未实操验收。
